## Requirement changes

| ID | Original requirement (P4A) | Revised requirement | Why it changed |
| :---- | :---- | :---- | :---- |
| R5 | (New) Agents must be able to discover active peers through a shared registry instead of requiring every peer address to be entered by hand. AC: *With a registry running, agents A and B configured with the registry URL appear in each other’s `GET /a2a/peers` within 5 s without manual `allowedPeers` entries; `a2a_ask` by peer name succeeds; after B stops and its heartbeat expires (10 s), B disappears from A’s peer list and `a2a_ask(peer="B")` fails with `Unknown A2A peer "B"`.* | (New, revised) The set of peers an agent can reach must be defined once per project in the plugin’s `a2a.allowedPeers` config and be identical for every session in that project; the local control API serves that list at `GET /a2a/peers`, and every name in it is addressable by name through `a2a_ask`. | **Feasibility and checkability.** The plugin is loaded into each opencode process and owns no long-lived service, and the repository defines no registry protocol, so “a shared registry” as stated means building and supervising a separate always-on process plus a liveness/heartbeat protocol — outside the feature’s process model. Its acceptance criteria also pin wall-clock behaviour (“within 5 s”, “heartbeat expires (10 s)”), which no deterministic test can check; a timing-sensitive test would only measure how fast the CI runner is. **What the users actually needed** (S-8 “keep track of all of the IPs”, O-8/O-9 “giving them the addresses”) was one place that knows the addresses instead of typing every address into every session — that is kept. What is dropped is the registry service and its liveness timing; the original service-based form is recorded here rather than silently deleted, so it can be built when a registry service exists to talk to. |

## Step 3: run, triage, and fix

Run from `packages/plugin-a2a` (never the repo root):

```
bun test
137 pass, 0 fail, 1276 expect() calls — 15 files (131 pre-existing tests + 6 properties)
```

No property failed against the current code, so this step needed no code fix (the handout allows that outcome). Three things were checked instead of assumed:

1. **The properties are not vacuous.** Each was mutation-checked: disabling URL validation in `config.ts` turned R1 red; recording outbound tasks as `inbound` in `conversation.ts` turned R2 red; swallowing the permission-denial branch in `session.ts` turned R3 red; making `addPeer` write nothing in `peers.ts` turned R5 red. Every mutation was reverted and the suite returned to green.
2. **The new tests run in the required place.** `turbo.json` already lists `@opencode-ai/plugin-a2a#test` (`dependsOn: []`), so `bun turbo test` in CI runs this suite; the tests sit next to `packages/plugin-a2a/test/` and use `bun test`, the package’s own runner.
3. **R4 is kept but has no property in this submission.** Its failure mode is real and was confirmed by inspection: `grep -rn "Authorization|bearer|https" packages/plugin-a2a/src` returns nothing, so neither the bearer token nor the HTTPS restriction exists yet. It stays in the table unchanged rather than being revised into something weaker; the gap is carried forward instead of quietly dropped.
